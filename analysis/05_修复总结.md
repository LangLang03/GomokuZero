### 1.2 竞态与性能（原问题 2）

**TSan / ASan / UBSan 结论：无数据竞争、无内存错误。**
所谓"竞态导致的性能下降"实为**逻辑层面的线程碰撞**——多线程选中同一未展开
子节点后走 `Retry` 并 `yield()`，白耗 playout 预算。

补上 `retries` profile 指标后，代价首次可量化：

| virtual_loss | 重试/评估 | s/game |
|---:|---:|---:|
| 1 | 637 | 2.09 |
| 3（旧默认） | 720 | 1.66 |
| **8（新默认）** | **523** | **1.56** |
| 20 | 723 | 1.92 |

另修两处：

- **虚拟损失符号反向**：原实现给被占用子节点的 `value_sum` 加**正值**，
  使其**更有吸引力**，与虚拟损失目的相反。
- **跨批种子重复**：固定 `GOMOK_SEED` 时每次 `run_batch()` 重建同一随机流，
  每批重放完全相同的对局，回放缓冲区被重复样本填满。

自对弈实测：**7.30 s/局 → 6.26 s/局**（batch 目标 128→32，重试 -32%）。

### 1.3 算法（原问题 3）

| 问题 | 修复 | 实测 |
|---|---|---|
| 伪 KL 驱动学习率死亡螺旋 | 删除反馈控制，改预热 + 余弦调度 + 只读 KL 探针 | 30 批内 lr× 从 1.0 掉到 0.132 → 现在按调度正常衰减（0.0020 → 0.00044） |
| 人类棋谱 one-hot（熵 0.000） | 基于 occupancy mask 的标签平滑 | 占用格概率恒为 0 |
| 无 Dirichlet 根噪声 | `(1-eps)P + eps*Dir` | — |
| 温度恒为 1.0 | 前 30 手 1.0，之后 0.5，可配 | — |
| `MAX_CAND=40` → 82.5% 位置被标"绝不可下" | 提到 60 可配 + 未访问合法位保留质量 | — |
| 验证指标不反映棋力 | 新增 `play_match` 真实对局评估（W/L/D + score）、真 KL、checkpoint 区分训练/推理形式 | — |
| 无数据增强 | 棋盘 8 重对称（在线变换） | — |
| `weight_decay` 两端不一致（CPU 0 / CUDA 0.01） | 统一为可配，默认 1e-4 | — |
| `clip_grad_norm(10.0)` 形同虚设 | 降到 2.0 可配 | — |

## 3. 明确未做的三项

| 项 | 为什么不做 | 影响 |
|---|---|---|
| **MCTS 子树复用** | 需要重写竞技场分配协议：promote 后新根的子节点不再落在 `[1, count)`，直接搬迁会破坏其他节点的 `child_begin`。试做后发现在当前追加式分配下无法安全实现，已完整撤销，不留半成品 | 每步 400 playout 从零重建，估计可省 30–50% 评估 |
| **正式验收 playout** | 依赖子树复用降低成本。当前逐局面推理（batch=1）约 140 ms/次，400 playout 的正式对局耗时不可接受 | 评估用的是浅搜索（默认 30） |
| **异步推理搬运** | 审查报告本身要求先由 profile 证明 H2D/D2H 占比显著，目前没有该数据 | 未知 |

### 与修复前的同类运行对比

| 指标 | 修复前（30 批） | 修复后（30 批） |

## 5. 训练成本提醒

当前架构自对弈 **6.26 s/局**（400 playout，RTX 5060 Laptop）。
按 README 的 79 批 × 64 局（约 5,056 局）推算约 **4–6 小时**。

这是把参数量从 32.6 万提到 810 万的直接代价。若需缩短，可：
降低 `--playout`、减小 `--batch-games`、或回调 `NetConfig` 的层数/通道数
（改 `src/net_config.h` 一处，其余全部派生）。
